# 20. 로그인 · 인증

인증 방식 전반(JWT, 역할, 접두어 규칙)은 [ADR-0003](../../adr/0003-auth-jwt.md), 공통 규칙은 [00-공통](00-공통.md).

## 20-1. 관리자 로그인 `/admin/login`

**코드**: `admin/pages/auth/Login.tsx`, 스토어 `shared/stores/adminAuthStore.ts`.

- 로그인 ID·비밀번호 → `POST /api/v1/auth/login` → `accessToken`·`member`(`roleCode`, `permissions`)를 관리자 스토어에 저장 → `/admin`.
- 로컬 관리자 `admin/1234`(`AdminAccountInitializer`). 회원(USER) 계정으로도 로그인 자체는 되지만 관리자 API가 403이라 화면이 비어 보인다.
- `/login`·`/signup`은 `/admin/login`·`/admin/signup`으로 리다이렉트.

체크포인트: 올바른 자격 → 대시보드, 사이드메뉴가 권한대로 노출. 틀린 비밀번호 → 오류 메시지(400/401), 대시보드 접근 시 `/admin/login`으로.

## 20-2. 관리자 회원가입 `/admin/signup`

**코드**: `admin/pages/auth/Signup.tsx` → `POST /api/v1/auth/signup`.

- 만들어지는 계정은 **USER 역할**이다(관리자가 아님). 관리자 계정은 `/admin/system/admins`에서 시스템 관리자가 만든다.
- **알려진 문제**: 이 페이지는 "관리자 가입"처럼 보이지만 관리자 권한을 주지 않아 혼란을 준다 → 7단계에서 삭제 예정.

## 20-3. 회원 로그인 `/user/login`

**코드**: `user/pages/UserLogin.tsx`, 스토어 `shared/stores/authStore.ts`.

- 아이디/비밀번호(`POST /api/v1/auth/login`) 또는 소셜 3종 버튼. 성공 시 `/user`로.
- 비활성(차단·탈퇴) 회원은 로그인 실패(`MemberService.login`에서 `active` 확인).

## 20-4. 이메일 회원가입 `/user/signup` → `/user/signup/email`

**코드**: `user/pages/UserSignup.tsx`(방법 선택), `user/pages/EmailSignup.tsx`(3단계 폼).

1. 이메일 입력 → `POST /api/v1/public/email/send-code` (Gmail SMTP로 6자리 숫자 코드 발송, 유효 5분 `app.mail.verification-code-expiry`, `tb_email_verifications`에 기록).
2. 코드 입력 → `POST /api/v1/public/email/verify-code`.
3. 아이디(영문·숫자·언더스코어)·비밀번호(영문+숫자+특수문자 8자 이상)·이름·전화(선택) → `POST /api/v1/auth/signup` → `/user/login`.

체크포인트: 코드 없이 3단계로 못 넘어감. 비밀번호 규칙 위반 400. 같은 아이디 재가입 → 409/400(`MEMBER_ALREADY_EXISTS`). **메일 발송은 `application-secret.yml`의 Gmail 값이 있어야 동작**(없으면 1단계에서 실패 — 로컬 검증은 가입 API 직접 호출로 대체).

## 20-5. 소셜 로그인 (카카오·네이버·구글)

**코드**: `user/pages/UserLogin.tsx`(버튼) → 각 `GET /api/v1/public/oauth/{provider}/config`로 `clientId`·`redirectUri`를 받아 제공자 인증 페이지로 이동 → `/user/oauth/callback/{provider}?code=...`(`user/pages/OAuthCallback.tsx`) → `POST /api/v1/public/oauth/{provider}` (code 교환은 서버 `KakaoOAuthService` 등이 수행) → 토큰 저장 → `/user`.

- 첫 로그인이면 `provider`·`providerId`로 USER 회원을 자동 생성(`MemberService`).
- 키는 `application-secret.yml`/환경변수. 리다이렉트 URI는 `http://localhost:3000/user/oauth/callback/{provider}`로 고정(운영 도메인은 8단계에서 환경변수화 필요).

체크포인트: 버튼 클릭 시 제공자 로그인 페이지로 이동(여기까지는 키 없이도 config 200 확인 가능). 실계정 완주는 수동.

## 20-6. 로그아웃 · 탈퇴

- 로그아웃은 클라이언트에서 스토어를 비울 뿐이다(서버 무효화 없음 — JWT, ADR-0003 트레이드오프).
- 탈퇴는 [60-마이페이지](60-마이페이지.md).

## 의도적 미구현 / 알려진 문제

- 비밀번호 찾기/재설정 없음.
- 차단된 회원의 기존 토큰은 만료(로컬 24h, 운영 1h)까지 유효.
- `/admin/signup`은 7단계에서 삭제.
