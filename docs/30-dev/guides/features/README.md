## ⚠️ 유지보수 규칙 — 기능을 고치면 가이드도 같이 고친다

- 화면·API의 **사용자 가시 동작**을 바꾸는 변경(추가·수정·삭제)은 해당 가이드를 **같은 브랜치에서** 고친다. 코드만 머지되면 이 폴더가 낡은 기대값을 검사하게 된다.
- 리팩토링·스타일 등 동작 불변 변경은 가이드 수정 불필요.
- 여러 메뉴에 걸치는 규칙(엔벨로프·권한·업로드)은 [00-공통.md](00-공통.md) 한 곳에만 적고 링크한다.
- "의도적 미구현/알려진 문제" 절의 항목이 구현되면 **그 줄을 지우는 것까지가 완료**다.
- 규칙의 앵커: 루트 `CLAUDE.md` §3, [`apps/CLAUDE.md`](../../../../apps/CLAUDE.md) §6, `verify` 스킬.

## 문서 형식 (새 메뉴 추가 시)

각 메뉴 절은 이 순서를 따른다: **URL·코드 위치 → 기능(사용자가 할 수 있는 것) → 사용 API → 테스트 체크포인트 → 의도적 미구현/알려진 문제**. 추측 서술 금지 — 코드에서 확인한 동작만 적는다. 확인 못 한 것은 "미확인"으로 남긴다.
