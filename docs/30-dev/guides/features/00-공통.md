# 00. 공통 — 레이아웃·API 규칙·권한

## 사용자 레이아웃 (`apps/frontend/src/user/layouts/UserLayout.tsx`)

- **헤더**: 로고(`/logo.png`, 저장소 `apps/frontend/public/`) + 메뉴 HOME·공지사항·인테리어(드롭다운: 현장시공·셀프시공·인테리어스토리)·자주묻는질문·견적문의. 오른쪽에 로그인, 로그인 상태면 사용자 드롭다운(마이페이지·로그아웃). **자유게시판 메뉴와 회원가입 버튼은 `shared/constants/features.ts`(`FEATURES.freeBoard`·`FEATURES.signup`)로 숨겨 둔 상태**(2026-10-13, 사용자 결정) — 코드·라우트(`/user/free`, `/user/signup`)는 그대로라 URL 직접 접속은 된다.
- 스크롤 10px 넘으면 헤더에 그림자. 페이지 이동 시 모바일 메뉴 닫힘 + 맨 위로 스크롤.
- **모바일(≤ 768px)**: 햄버거 버튼으로 메뉴 펼침. **769~1024px**(태블릿·좁은 창)에서는 로고 글자를 숨기고 메뉴 여백을 줄여 메뉴 5개 + 로그인이 한 줄에 들어간다(2026-10-12 780·900px 확인, 가로 스크롤 없음).
- **푸터**: 로고·슬로건·서비스/고객지원 링크·업체 정보(주소·전화·네이버 블로그/예약 — `shared/constants/business.ts`, [business.md](../../../00-common/business.md)). 대표명·사업자번호는 확정 전이라 표시하지 않는다.
- **SEO**: `public/robots.txt`(`/admin`·`/api` 차단), `/sitemap.xml`은 백엔드 생성(공개 라우트 + 인테리어 상세). 메타는 `usePageMeta`.
- **팝업 레이어**(`user/components/PopupLayer.tsx`): 홈 진입 시 `GET /api/v1/public/popups/active`로 활성 팝업을 받아 띄운다. "하루동안 열지 않기"는 쿠키(`popup_hide_{id}`, 자정까지)로 처리.

## 관리자 레이아웃 (`apps/frontend/src/admin/layouts/AdminLayout.tsx`)

- 왼쪽 사이드메뉴는 DB 메뉴(`GET /api/v1/admin/menus/type/ADMIN`)를 **보유 권한(`permissions`)으로 필터**해 그린다. 헤더에 로그인한 관리자 이름, 드롭다운 로그아웃.
- 라우트 가드 `shared/components/PermissionGuard.tsx` + `shared/constants/permissions.ts`(`menuPermissionMap`): 경로별 필요 권한 코드. 매핑에 없는 경로는 통과(7단계부터 관리자 전 경로가 매핑돼 있다). **서버가 별도로 역할을 강제하므로 보안 장치가 아니다.**

## API 규칙 (전 화면 공통)

- 베이스 `/api/v1`. 프론트는 상대경로로 호출하고 Vite 프록시(로컬)·nginx(운영 예정)가 8080으로 넘긴다.
- 접두어로 권한이 결정된다([ADR-0003](../../adr/0003-auth-jwt.md)):

  | 접두어 | 요구 | 실패 시 |
  |---|---|---|
  | `/api/v1/public/**`, `/api/v1/auth/login`·`signup`, `/uploads/**`, `/api/v1/health` | 없음 | — |
  | `/api/v1/user/**`, `/api/v1/auth/withdraw` | 로그인(회원 또는 관리자 토큰) | `401 {"error":"C004"}` |
  | `/api/v1/admin/**` | 관리자 역할(SYSTEM/OPERATION/GENERAL_ADMIN) | 비로그인 `401 C004`, 회원 토큰 `403 C005` |

- 인증은 `Authorization: Bearer <JWT>`. 토큰은 `POST /api/v1/auth/login` 응답 `data.accessToken`. 프론트는 경로가 `/admin`으로 시작하면 관리자 스토어, 아니면 회원 스토어의 토큰을 붙인다(`shared/api/client.ts`). 401이면 해당 스토어를 비우고 로그인 화면으로, 403이면 "권한이 없습니다" 메시지.
- 응답 엔벨로프: `{ success, data, message, error, timestamp }`. 목록은 `data = { content, pageNumber, pageSize, totalElements, totalPages, first, last }` 형태(`PageResponse`). 페이징 파라미터 `page`(0부터)·`size`.
- 검증 실패·타입 불일치(없는 enum 값 등)·본문 파싱 실패·필수 파라미터 누락 → 400(`C001`), 없는 리소스 404(도메인 코드 예: `CO001` 콘텐츠 없음), 그 외 → 500(`C002`, 메시지는 "요청을 처리하지 못했습니다." 고정 — 내부 예외 문구는 서버 로그에만).

## 권한 코드 (`tb_permissions.perm_code`, V2+V3 시드 13개)

메뉴 접근용 `MENU_DASHBOARD`·`MENU_POST`·`MENU_INTERIOR`·`MENU_POPUP`·`MENU_USER`·`MENU_CONTENT`·`MENU_SYSTEM_MENU`·`MENU_SYSTEM_BOARD`·`MENU_SYSTEM_ROLE`·`MENU_SYSTEM_ADMIN` 10개 + 데이터 `DATA_READ`·`DATA_WRITE`·`DATA_DELETE`. 역할별 보유: SYSTEM_ADMIN 13 · OPERATION_ADMIN 8 · GENERAL_ADMIN 6 · USER 0 (`tb_role_permissions` 27행). **모든 관리자 역할이 운영 메뉴(대시보드·시공사례·공지/FAQ/견적문의·팝업)를 보고, 컨텐츠·시스템 메뉴는 SYSTEM_ADMIN만**(V3, 7단계). 정본은 DB 시드이고 화면은 `/admin/system/roles`. (`AdminMenuTreeTest`·`FlywayMigrationTest`)

## 파일 업로드

- `POST /api/v1/user/files/upload` (multipart `file`, `refType`, `refId`) — 로그인한 회원·관리자 모두 가능. 허용 확장자 jpg·jpeg·png·gif·webp·bmp, 최대 10MB(`spring.servlet.multipart`).
- 저장 위치 `FILE_UPLOAD_DIR`(기본 `apps/backend/uploads`)의 `yyyy/MM/dd/{uuid}.{ext}`, 이미지는 `thumb_` 썸네일 자동 생성. 응답 `fileUrl`(`/uploads/...`)·`thumbnailUrl`.
- CKEditor 본문 이미지(`shared/utils/ckEditorUploadAdapter.ts`)와 인테리어 대표 이미지, 블로그 이관 도구가 같은 API를 쓴다.
