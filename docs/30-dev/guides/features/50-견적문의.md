# 50. 견적문의 `/user/inquiry` → 관리자 문의 관리 `/admin/posts/qna`

**코드**: `user/pages/InquiryPage.tsx`, `admin/pages/InquiryManagement.tsx`, 엔티티 `Inquiry`(`tb_inquiries`).

## 사용자: 문의 작성 (비로그인 가능)

- 폼: 이름·연락처·시공 유형·문의 내용은 필수(`@NotBlank`), 이메일·예산·장소는 선택. 시공 유형(`apartment` 아파트 · `villa` 빌라 · `office` 사무실 · `store` 상가 · `other` 기타), 예상 예산(`under1000` 1,000만원 이하 · `1000-3000` · `3000-5000` · `over5000` 5,000만원 이상 · `consult` 상담 후 결정), 시공 장소, 문의 내용(필수). 코드값은 DB에 문자열 그대로 저장된다(enum 아님).
- 제출 → `POST /api/v1/public/inquiries` → 접수 완료 화면("견적문의가 접수되었습니다!") + "추가 문의하기".
- 오른쪽 Contact 카드(전화 상담·네이버 블로그/예약·오시는 길)는 `shared/constants/business.ts`의 값(블로그 공개 정보, [business.md](../../../00-common/business.md)).

## 관리자: 문의 관리

- 상단 카드: 전체·대기중·처리중·완료 건수. 목록(`GET /api/v1/admin/inquiries?page&size&status`): 번호·상태·이름·연락처·시공유형·예산·문의일시·메모. 상태 필터.
- 행 버튼: 상세 보기(`GET /{id}`), 상태 변경(`PATCH /api/v1/admin/inquiries/{id}/status` `{status}`), 메모(`PATCH /{id}/memo` `{memo}`).
- 상태값은 문자열 `PENDING`(대기, 기본) · `IN_PROGRESS`(처리중) · `COMPLETED`(완료) — enum이 아니라 관리자 화면(`InquiryManagement.tsx`)이 정하는 값이다.

## 테스트 체크포인트

- 비로그인으로 폼 제출 → 접수 화면 → 관리자 목록에 "대기" 1건(2026-10-12 실측). 필수값 비우면 제출 안 됨(프론트 검증) / API 직접 호출 시 400.
- 상태를 "완료"로 바꾸면 상단 카드 숫자가 바뀜. 메모 저장 후 목록에 표시.
- 접수 시 `app.inquiry.notify-to`(환경변수 `INQUIRY_NOTIFY_TO`)가 설정돼 있으면 그 주소로 "[수디자인] 새 견적문의: {이름}" 메일이 비동기로 간다(`InquiryNotifier`). 비어 있으면 알림 없음. 발송 실패는 로그만 남고 접수는 성공. 관리자 대시보드 첫 카드에 대기 문의 수가 뜬다([70-admin](70-admin.md)).

## 의도적 미구현 / 알려진 문제

- 사용자는 자기 문의를 조회할 수 없다(접수 번호 없음).
- 첨부파일 없음.
